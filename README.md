# Bailanysta

## Демо (задеплоено)

- **Приложение:** https://bailanysta-one.vercel.app
- **API:** https://bailanysta-cg9h.onrender.com/api
- **Репозиторий:** https://github.com/asylansson/Bailanysta

Frontend — Vercel, backend — Render (оба на бесплатном тарифе). Гости
(без входа) сразу видят заполненную ленту, сообщества и посты — база
данных предзаполнена синтетическими "ботами" (см. "Известные ограничения"
про сброс данных на Render).

Веб-платформа социальной сети: пользователи входят через свой Google-аккаунт,
публикуют посты, лайкают и комментируют (в том числе древовидными ответами на
ответы, как на Reddit/Quora), подписываются друг на друга, переписываются личными
сообщениями с теми, с кем взаимно подписаны, создают и вступают в сообщества по
интересам, ищут людей и сообщества, настраивают профиль (имя, никнейм, аватар из
18 готовых иконок с выбором по гендерной подаче) и выбирают один из трёх языков интерфейса (казахский, русский,
английский) — и всё это на собственном REST API.

Название "Bailanysta" — от казахского "байланыс" (связь, on air / in touch).

## Стек и почему он выбран

| Слой     | Технология                          |
|----------|--------------------------------------|
| Frontend | React 18 + Vite + React Router + Tailwind CSS |
| Backend  | Node.js + Express                    |
| Аутентификация | Google Sign-In (Google Identity Services) + собственные JWT-сессии |
| Хранилище| JSON-файл (`backend/data/db.json`)   |
| Локализация | Собственный контекст i18n (kk/ru/en) без сторонних библиотек |

- **React + Vite** — минимальный конфиг, мгновенный hot-reload, стандарт индустрии для SPA.
- **Tailwind CSS** (с `darkMode: "class"`) — позволяет быстро собрать аккуратный, единообразный UI и параллельно поддерживать светлую/тёмную тему через `dark:`-варианты классов, без дублирования CSS.
- **React Router** — клиентский роутинг между лентой, профилями, сообщениями, сообществами, поиском и настройками.
- **Express** — минимальный, предсказуемый REST API без лишней инфраструктуры.
- **Google Sign-In (`@react-oauth/google` + `google-auth-library`)** — вместо самодельной регистрации по имени. Даёт реальную верифицированную личность (email), настоящее имя и фото профиля без необходимости хранить пароли самим. Верификация ID-токена происходит на сервере — единственный внешний сервис в проекте вызывается именно с бэкенда, как того требует ТЗ.
- **`jsonwebtoken`** — после проверки Google-токена сервер выдаёт свою короткую сессию (JWT), чтобы не гонять Google-токен на каждый запрос; фронтенд посылает его в `Authorization: Bearer`.
- **JSON-файл вместо БД** — на объёме задачи (users/posts/comments/follows/notifications/conversations/messages/communities, single-instance dev-сервер) полноценная СУБД избыточна. Файл читается/пишется через `fs/promises` с сериализованной очередью записи (см. `db.js`), что даёт персистентность между перезапусками без установки базы данных. Осознанный компромисс — см. "Компромиссы".
- **Собственный i18n вместо `react-i18next`** — при трёх языках и известном наборе экранов простой `t(key)` поверх вложенного объекта-словаря (`frontend/src/i18n/`) даёт всё необходимое (интерполяция, склонения по числу) без лишней зависимости.

## Функциональность

**Уровень 1–2 (обязательные):**
- Профиль пользователя с формой создания постов.
- Общая лента постов всех пользователей (автор, текст, время).
- Собственный backend (Express + REST API), роутинг между страницами.

**Реализовано сверх обязательного:**
- **Вход через Google** вместо придуманного имени — реальная личность (email, имя,
  фото профиля), без паролей на нашей стороне.
- Светлая/тёмная тема с сохранением выбора.
- Лайки постов и комментариев.
- Комментарии с вложенными ответами произвольной глубины (дерево, как в Reddit/Quora).
- Редактирование собственных постов (право проверяется по ID из подписанной сессии).
- Подписки между пользователями.
- Уведомления о лайках, комментариях, ответах и подписчиках.
- **Генератор случайного статуса** — вместо интеграции внешнего AI API (ChatGPT), по
  договорённости, кнопка "🎲 Случайная идея" подставляет одну из ~15 заготовленных
  фраз-настроений (`frontend/src/statusPhrases.js`), переведённых на все три языка
  интерфейса — фраза подставляется на том языке, который выбран в настройках.
- Скелетоны-плейсхолдеры вместо текста "Загрузка...".
- **Форма создания поста — на странице "Лента"**, а не в профиле: пишете и сразу видите
  пост среди остальных, без перехода на отдельную страницу. Страница профиля теперь
  предназначена только для просмотра своих прошлых постов и списков
  подписчиков/подписок; создание постов в сообществах по-прежнему происходит на странице
  самого сообщества.
- **Более заметная главная навигация** — "Лента", "Сообщения", "Сообщества" оформлены
  крупными акцентными иконками-квадратами (без подписи текстом, чтобы ширина кнопок не
  зависела от языка интерфейса), заметно крупнее компактной иконки поиска и аватара
  профиля рядом.
- **Название "Bailanysta"** вынесено отдельной строкой над иконками навигации, по центру,
  фирменным шрифтом (Poppins) — без логотипа-пиктограммы.
- **Настройки, переключение темы и выход из аккаунта** — теперь на странице профиля
  (иконки рядом с именем пользователя), а не в навбаре; на странице ленты вместо этого
  появился колокольчик уведомлений.
- Хэштеги в тексте поста подсвечиваются фиолетовым (кликабельного поиска по ним на
  странице ленты сейчас нет — по договорённости поиск убран со страницы ленты, см. ниже).
  Backend по-прежнему поддерживает `GET /api/posts?q=` для полнотекстового поиска по
  постам, если понадобится вернуть эту возможность в интерфейс.
- **Личные сообщения** ("Сообщения" в навбаре, рядом с "Лентой") — переписка возможна
  только между людьми, которые взаимно подписаны друг на друга ("друзья"); никто
  посторонний переписку не видит. Если открыть страницу сообщения с человеком, с
  которым подписка не взаимна, вместо чата показывается кнопка "Подписаться".
- **Сообщества** — публичные (видны всем) или приватные (видны только тем, кто состоит
  во взаимной подписке хотя бы с одним участником сообщества — то есть "друзьям
  участников"). Внутри сообщества можно публиковать посты по теме сообщества; эти посты
  не попадают в общую ленту.
- **Отдельная страница поиска** (`/search`) — поиск людей и сообществ по имени/никнейму/
  названию. Клик по человеку открывает страницу личных сообщений с ним (с кнопкой
  "Подписаться", если вы ещё не друзья); клик по сообществу открывает его страницу.
  Хранит историю недавних запросов (в браузере), которую можно очистить в настройках.
- **Поиск также встроен прямо в "Сообщения" и "Сообщества"** — на странице "Сообщения"
  поле поиска фильтрует уже открытые переписки по имени собеседника (на клиенте, без
  обращения к серверу); на странице "Сообщества" поле поиска ищет среди сообществ,
  видимых вам, через тот же `GET /api/communities?q=`, что использует `/search`. На
  странице "Лента" полноценного поля поиска намеренно нет — по прямой просьбе; вместо
  него рядом с колокольчиком уведомлений есть значок-кнопка "🔍", которая ведёт на
  отдельную страницу `/search` (поиск людей и сообществ) — это единственное место в
  приложении, откуда можно попасть на `/search`; в общем навбаре такой иконки нет.
- **Изменённый алгоритм ленты** — теперь показывает посты только от тех, на кого
  подписан текущий пользователь (плюс собственные посты), а не вообще всех — независимо
  от того, подписаны ли эти люди в ответ. Гости без входа по-прежнему видят все посты
  (для ознакомления с приложением).
- **18 иконок-аватаров** в мультяшном стиле (лев, волк, носорог, медведь, тигр, лиса,
  свинья, корова, панда, кролик, пингвин, коала, сова, обезьяна, плюс отдельно кот/кошка
  и пёс/собачка — по паре на каждого) на выбор в настройках — как альтернатива фото из
  Google. Гендерная подача каждой иконки задаётся минимальными визуальными признаками:
  "мужские" — простые брови, "женские" — реснички, бантик и лёгкий румянец, "нейтральные"
  — ни того, ни другого, — так что и мальчики, и девочки, и те, кто не хочет привязки к
  полу, могут выбрать то, что им ближе.
- **Страница настроек** (`/settings`) — имя, фамилия, никнейм (начинается с `@`,
  проверяется на уникальность), выбор аватара, язык интерфейса, очистка истории поиска.
- **Три языка интерфейса** — казахский, русский (по умолчанию), английский; выбор
  сохраняется на аккаунте и применяется сразу на всех страницах.
- **Список подписчиков/подписок** — на странице профиля счётчики "N подписчиков" и
  "N подписок" кликабельны и открывают всплывающий список этих людей со ссылками на их
  профили.
- **"Написать" на странице "Сообщения"** — кнопка открывает список взаимных друзей, с
  которыми ещё нет переписки (`GET /api/users/:id/friends`, пересечение "на кого подписан"
  и "кто подписан на меня"), и позволяет начать разговор в один клик; друзья, с которыми
  переписка уже есть, из списка исключаются.
- **Время под постами, комментариями и сообщениями** — теперь относительное и понятное с
  первого взгляда ("только что", "5 минут назад", "Вчера, 14:32"), а не всегда полная
  дата; для всего, что старше вчерашнего дня, показывается компактная дата ("15 сент." или
  "15 сент. 2025", если это не текущий год). Время вынесено в правый верхний угол
  карточки/строки, на одну линию с именем автора, а не сразу после имени.
- **Заголовки страниц** ("Лента", "Сообщения", "Сообщества", "Поиск", "Настройки",
  "Уведомления") — теперь по центру страницы, тем же фирменным шрифтом (Poppins), что и
  название "Bailanysta" в шапке, и менее массивным начертанием. Кнопки-действия рядом с
  заголовком (например, "Создать сообщество" или "Написать") прижаты к правому краю той
  же строки и оформлены как компактная контурная "таблетка", а не сплошная кнопка —
  заметно мельче самого заголовка.

## API

Все эндпоинты, требующие личность, берут её из заголовка `Authorization: Bearer <токен>`,
никогда из тела запроса — токен подписан на сервере, подделать чужого автора нельзя.

| Метод | Путь | Auth | Описание |
|---|---|---|---|
| POST | `/api/auth/google` | — | обменять Google ID-токен на сессию `{ credential }` -> `{ token, user }` |
| GET | `/api/posts?q=&communityId=` | опц. | лента по подпискам (или посты сообщества, если указан communityId) |
| GET | `/api/posts/author/:userId` | опц. | посты одного автора |
| GET/POST/PATCH | `/api/posts[/:id]` | POST/PATCH обязательна | создать/редактировать пост `{ text, communityId? }` |
| POST | `/api/posts/:id/like` | обязательна | лайк/анлайк |
| GET/POST | `/api/posts/:postId/comments` | POST обязательна | дерево комментариев / создать `{ text, parentId? }` |
| POST | `/api/comments/:id/like` | обязательна | лайк/анлайк комментария |
| GET | `/api/users/me` | обязательна | мои полные настройки |
| PATCH | `/api/users/me` | обязательна | обновить `{ firstName, lastName, nickname, avatarPreset, language }` |
| GET | `/api/users/:id` | опц. | публичный профиль (+ `isMutualFriend`) |
| GET | `/api/users/:id/followers` / `/following` | опц. | список подписчиков / на кого подписан |
| GET | `/api/users/:id/friends` | опц. | взаимные подписки (пересечение followers ∩ following) |
| POST | `/api/users/:id/follow` | обязательна | подписаться/отписаться |
| GET | `/api/notifications` / `POST /read` | обязательна | уведомления текущего пользователя |
| GET | `/api/conversations` | обязательна | список переписок (только с взаимными друзьями) |
| GET | `/api/conversations/:userId` | обязательна | статус (мутуальный ли друг) + данные собеседника |
| GET/POST | `/api/conversations/:userId/messages` | обязательна | история / отправить `{ text }` — 403, если не взаимные друзья |
| POST | `/api/conversations/:userId/read` | обязательна | отметить переписку прочитанной |
| GET/POST | `/api/communities` | POST обязательна | список/поиск (видимость учитывает приватность) / создать `{ name, description, visibility }` |
| GET | `/api/communities/:id` | опц. | детали (404, если приватное и не видно вам) |
| POST | `/api/communities/:id/join` / `/leave` | обязательна | вступить/выйти |
| GET | `/api/search?q=` | опц. | `{ users, communities }` по имени/никнейму/названию |

## Установка и запуск

Требуется Node.js 18+ и Google-аккаунт для создания OAuth Client ID (бесплатно).

### 1. Получить Google OAuth Client ID

1. [console.cloud.google.com](https://console.cloud.google.com/) → создать проект.
2. **APIs & Services → OAuth consent screen** → "External" → заполнить обязательные поля → сохранить.
3. **APIs & Services → Credentials → Create Credentials → OAuth client ID**, тип **Web application**.
4. В **Authorized JavaScript origins** добавить `http://localhost:5173`.
5. Скопировать **Client ID** (секрет не нужен).

### 2. Переменные окружения

**Backend** (`backend/.env`, скопировать из `.env.example`):
```
JWT_SECRET=любая-длинная-случайная-строка
GOOGLE_CLIENT_ID=xxxxx.apps.googleusercontent.com
```

**Frontend** (`frontend/.env`, скопировать из `.env.example`):
```
VITE_GOOGLE_CLIENT_ID=xxxxx.apps.googleusercontent.com
```

### 3. Запустить

```bash
cd backend && npm install && npm start      # порт 4000
cd frontend && npm install && npm run dev   # порт 5173, отдельный терминал
```

Открыть [http://localhost:5173](http://localhost:5173).

## Как проверить работу

1. Настроить Google Client ID, запустить backend/frontend.
2. **Вход** — "Профиль" → "Войти через Google".
3. **Лента, посты, лайки, комментарии, темы** — как раньше (см. историю разработки ниже).
4. **Сообщения** — откройте чужой профиль, подпишитесь; попросите второй аккаунт (или
   тестовый JWT, см. "Известные ограничения") подписаться в ответ — только тогда в
   "Сообщения" появится возможность переписки; до этого видна лишь кнопка "Подписаться".
5. **Сообщества** — "Сообщества" → "Создать сообщество", выберите публичное или
   приватное. Приватное будет видно в поиске/списке только тем, кто состоит во взаимной
   подписке хотя бы с одним участником. Внутри сообщества можно публиковать посты — они
   не попадут в общую ленту.
6. **Поиск** — "🔍" в навбаре → `/search`, найдите человека или сообщество; клик по
   человеку откроет страницу сообщений с ним, клик по сообществу — его страницу.
   Проверьте, что запрос сохранился в "недавние", а очистка истории в настройках его
   убирает.
7. **Настройки** — на своей странице профиля (`/u/<ваш id>`) нажмите на значок шестерёнки
   рядом с кнопкой выхода → выберите один из 18 аватаров (обратите внимание на пары
   "кот/кошка" и "пёс/собачка", а также на брови/реснички+румянец у остальных иконок —
   это и есть выбор по гендерной подаче), задайте имя/фамилию/никнейм (обязательно с
   `@`), сохраните — изменения сразу видны в навбаре и на новых постах. Переключите
   язык — весь интерфейс сразу переключится, включая фразы генератора случайных идей.
8. **Лента по подпискам и создание постов** — форма поста теперь на самой странице
   "Лента" (сверху), а не в профиле. Новый аккаунт без подписок видит в ленте только
   свои посты; после подписки на кого-то его посты появляются.
9. **Подписчики/подписки** — на странице своего или чужого профиля нажмите на
   "N подписчиков" или "N подписок" — откроется список этих людей со ссылками на их
   профили.

## Процесс разработки

Задача разрасталась по итогам нескольких раундов обсуждения:
1. Уровень 1–2 — статичная структура компонентов, собственный Express API, роутинг.
2. Лайки/комментарии-дерево/подписки/уведомления/тёмная тема/поиск постов/скелетоны +
   генератор случайного статуса вместо интеграции внешнего AI API.
3. Замена самодельной идентификации по имени на вход через Google (устранение проблемы
   одинаковых имён и подделки авторства) — потребовала сквозного перехода модели данных
   на `authorId` вместо денормализованного `authorName`, с сериализацией имени/фото "на
   лету" при каждом ответе API (`helpers.js#serializePost/serializeComment`), а не при
   записи, чтобы смена имени в Google-аккаунте сразу отражалась во всех старых постах.
4. Личные сообщения, сообщества, отдельная страница поиска с историей, смена алгоритма
   ленты на "по подпискам", 20 иконок-аватаров, страница настроек и полная локализация
   интерфейса на 3 языка.

Раунд 4 потребовал больше всего новых сущностей в модели данных: `conversations` +
`messages` (переписка привязана к паре `memberIds`, а не к одному "чату", и гейтится
проверкой `isMutualFollow` на каждой отправке — не только при создании), `communities`
(с `memberIds` и правилом видимости `canViewCommunity`, повторно использующим тот же
`isMutualFollow`), и поле `communityId` на существующих постах (вместо отдельной таблицы
"постов сообщества" — переиспользованы все существующие лайки/комментарии/редактирование
бесплатно). i18n сделан как простой `t(key)` поверх вложенного словаря с собственной
интерполяцией `{param}` и функцией склонения `tp(key, count)`, учитывающей разные правила
множественного числа для русского (1/2-4/5+), английского (1/иначе) и казахского (без
словоизменения по числу) — без сторонней библиотеки, так как набор экранов и языков
заранее известен и фиксирован.

Технический урок предыдущего раунда (не относится к этому): в ES-модулях `import`
поднимается выше остального кода файла, поэтому чтение `process.env` в константу на
верхнем уровне модуля (а не лениво внутри функций) может закэшировать `undefined`, если
`.env` грузится позже — актуально для любого модуля, импортируемого раньше вызова
`process.loadEnvFile()`.

Дизайн — минималистичный, бело-фиолетовая палитра (violet-600), карточки с мягкой тенью,
светлая/тёмная тема через `dark:`-варианты Tailwind.

## Компромиссы

- **JWT-сессия поверх Google вместо серверных сессий/куки** — проще для масштаба задачи,
  но украденный токен действителен до истечения срока (30 дней) без отзыва.
- **JSON-файл вместо базы данных** — очередь записи в `db.js` устраняет потерю данных
  при гонке запросов, но не масштабируется на много одновременных пользователей.
- **Переписка гейтится живым состоянием подписок**, а не отдельным списком "друзей" —
  если один из двух отпишется, история переписки станет недоступна до повторной взаимной
  подписки (проще для реализации, но не всегда ожидаемое поведение мессенджера).
- **Приватность сообщества проверяется через мутуальную подписку с любым участником**, а
  не только с создателем — так задание было явно сформулировано; при большом сообществе
  это делает приватность довольно "дырявой" (чем больше участников, тем больше шанс, что
  у постороннего найдётся среди них взаимный друг).
- **История поиска — в `localStorage`, а не на сервере** — она нужна только конкретному
  браузеру конкретного человека, серверное хранение не добавило бы ценности.
- **18 аватаров нарисованы как простые SVG-фигуры**, а не полноценные иллюстрации — стиль
  плоских "флэт"-иконок, узнаваемый по силуэту и одной-двум характерным деталям, но не
  фотореалистичный мультяшный рисунок. Гендерная подача обозначена минимально (брови ⁄
  реснички+румянец ⁄ ничего, без бантиков и прочих аксессуаров) — сознательно лёгкий, не
  стереотипный подход, а не полноценная разная одежда/причёски. Распределение "кто с
  бровями, кто с ресничками" сознательно перемешано по видам животных, чтобы не совпадать
  со стереотипом "сильное животное = мальчик, милое животное = девочка".
- **Генератор случайного статуса вместо AI API** — по договорённости; фразы переведены на
  все три языка интерфейса и подставляются на выбранном языке.
- **Уведомления опрашиваются (polling)**, а не push/WebSocket.
- **Без изображений в постах** — разрешено по ТЗ Уровня 1.

## Известные ограничения

- **Демо-пользователи ("Aigerim", "Nurlan", "Адилет") нельзя использовать для входа** —
  исторические сид-данные без Google-аккаунта. Чтобы протестировать сообщения/сообщества
  вдвоём без второго реального Google-аккаунта, можно сгенерировать тестовую JWT-сессию
  напрямую (см. `backend/auth.js#signSession`) и положить её в `localStorage` браузера
  под ключом `bailanysta_session` — так делалось при разработке для второй "личности".
- Токен сессии не привязан к устройству/IP, не отзывается раньше истечения срока.
- Нет пагинации ленты, комментариев, уведомлений, сообщений, поиска.
- **Render (бесплатный тариф) не даёт постоянного диска** — `backend/data/db.json`
  живёт в эфемерной файловой системе контейнера. При перезапуске backend'а
  (например, после простоя без запросов, "spin down") файл пересоздаётся заново из
  закоммиченного `backend/data/seed.json` — полностью синтетический набор
  пользователей/постов/сообществ (без реальных Google-аккаунтов, поэтому его можно
  спокойно хранить в публичном репозитории). Это значит, что любая активность
  реальных посетителей (новые аккаунты, лайки, комментарии) не переживёт перезапуск
  контейнера — компромисс, осознанно принятый ради бесплатного хостинга.
- Google Sign-In на задеплоенном фронтенде работает только если домен фронтенда
  добавлен в Authorized JavaScript origins использующегося OAuth-клиента в Google
  Cloud Console.
