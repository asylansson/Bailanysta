# Bailanysta

Полноценная социальная сеть: собственный Express REST API, вход через Google,
посты с лайками и древовидными комментариями, подписки и личные сообщения между
друзьями, публичные и приватные сообщества (ұйымдар), поиск, уведомления и
интерфейс на трёх языках (казахский, русский, английский).

Название — от казахского "байланыс" (связь, on air / in touch).

## Демо (задеплоено)

| | |
|---|---|
| 🌐 Приложение | https://bailanysta-one.vercel.app |
| ⚙️ API | https://bailanysta-cg9h.onrender.com/api |
| 📦 Репозиторий | https://github.com/asylansson/Bailanysta |

Frontend на Vercel, backend на Render (оба на бесплатном тарифе). Гости без
входа сразу видят заполненную ленту, сообщества и посты — база данных
предзаполнена синтетическим набором пользователей и контента.

## Функциональность

**Аккаунт и профиль**
- Вход через Google (без паролей на своей стороне) с собственной короткой
  JWT-сессией поверх проверенного Google ID-токена; кнопка входа отображается
  на том же языке, что выбран в интерфейсе.
- Имя, фамилия (необязательна), уникальный никнейм, аватар — фото из Google или
  один из 18 SVG-иконок (мужская/женская/нейтральная подача одним и тем же
  силуэтом животного).
- Приватный профиль — публикации, подписки, подписчики и сообщества видны
  только тем, кого владелец одобрил как подписчика.
- Меню профиля в шапке (клик по аватару) — быстрый доступ к профилю,
  настройкам, переключению темы и выходу из аккаунта, без перехода на
  отдельную страницу.
- Светлая/тёмная тема (переключается плавно, без резкой смены цветов), язык
  интерфейса — сохраняются на аккаунте; язык также переключается прямо в
  шапке по ссылкам EN/KZ/RU, доступным и гостям (английский — язык по
  умолчанию для новых посетителей).
- **Читаемые ссылки на профиль и сообщества** — `/u/<никнейм>` и
  `/communities/<никнейм>` вместо длинного технического id; если никнейм ещё
  не задан, используется короткий порядковый номер аккаунта.

**Посты и лента**
- Создание поста прямо на странице ленты; хэштеги в тексте кликабельны и
  подсвечены.
- Локальный (без внешних AI-платных API) помощник для постов: подстановка
  готовой идеи-фразы под настроение и подсказка хэштегов по ключевым словам и
  тону текста — работает офлайн, ничего никуда не отправляет.
- Лайки постов и комментариев; комментарии — дерево произвольной глубины
  (ответ на ответ), как на Reddit.
- Редактирование собственных постов; авторство проверяется по подписанной
  сессии, а не по данным из тела запроса.
- Лента "Рекомендации" (все посты за всё время, отсортированы по популярности
  с приоритетом интересов пользователя) и лента "Подписки" (только от тех, на
  кого подписан, по времени публикации).
- Дата и время везде показываются в одном и том же числовом формате
  (`ЧЧ:ММ`, `ДД.ММ`) независимо от выбранного языка интерфейса — так они
  остаются одинаково читаемыми на всех трёх языках, без разнобоя в стиле дат.

**Сообщества (ұйымдар)**
- Публичные (видны всем) и приватные (посты видны только участникам).
- У приватного сообщества страница (название, описание, число участников)
  видна всем так же, как у публичного — скрыты только посты; вместо кнопки
  "Вступить" — "Запросить вступление", а после отправки запроса кнопка
  становится зелёной "Запрошено!". Администратор одобряет или отклоняет заявки.
- Публикация постов по теме сообщества — не попадают в общую ленту.

**Сообщения и уведомления**
- Личная переписка доступна только между взаимными подписчиками ("друзьями");
  если подписка не взаимна, вместо чата — кнопка "Подписаться". Открытая
  переписка обновляется сама по себе (опрос раз в несколько секунд), не нужно
  выходить и заходить заново, чтобы увидеть новое сообщение.
- Уведомления о лайках, комментариях, ответах, новых подписчиках, заявках на
  подписку и заявках на вступление в сообщество.
- Сообщения недоступны гостям — ни через навигацию, ни по прямой ссылке (сразу
  ведёт на экран входа).

**Прочее**
- Полнотекстовый поиск людей и сообществ с историей запросов в браузере.
- Скелетоны-плейсхолдеры и анимации переходов вместо пустых экранов загрузки.
- Контент (посты, обсуждения под ними) есть на всех трёх языках интерфейса, в
  том числе смешанные по языку ветки комментариев под одним постом — типичная
  картина для многоязычного сообщества, а не искусственно разделённые "зоны".
- Раскладка проверена и работает одинаково на телефоне и на десктопе — шапка,
  кнопки действий и меню профиля не наезжают друг на друга ни на узких, ни на
  широких экранах.
- Иконки "Лента / Сообщения / Сообщества" в шапке на десктопе разворачивают
  подпись при наведении; на телефоне, где наведения как такового нет, это
  просто иконки без анимации. На десктопе разворачивание ограничено невидимой
  границей (ширина блока иконок сужается вместе с окном, лишнее обрезается),
  так что подпись не может наехать на переключатель языка или на аватар,
  сколько бы места ей ни хотелось.

## Стек и почему он выбран

| Слой | Технология |
|---|---|
| Frontend | React 18 + Vite + React Router + Tailwind CSS |
| Backend | Node.js + Express |
| Аутентификация | Google Identity Services + собственные JWT-сессии |
| Хранилище | JSON-файл (`backend/data/db.json`), сериализованная очередь записи |
| Локализация | Собственный контекст i18n (kk/ru/en), без сторонних библиотек |
| Деплой | Vercel (frontend) + Render (backend), оба free tier |

- **React + Vite** — минимальный конфиг, мгновенный hot-reload, стандарт для SPA.
- **Tailwind CSS** (`darkMode: "class"`) — единообразный UI и тёмная тема через
  `dark:`-варианты классов, без дублирования CSS.
- **Google Sign-In** вместо самодельной регистрации — реальная верифицированная
  личность (email, имя, фото) без хранения паролей. ID-токен проверяется на
  сервере (`google-auth-library`) — единственный внешний вызов в проекте идёт
  именно с бэкенда.
- **`jsonwebtoken`** — после проверки Google-токена сервер выдаёт свою короткую
  сессию, чтобы не гонять Google-токен на каждый запрос.
- **JSON-файл вместо СУБД** — на объёме задачи (single-instance dev-сервер)
  полноценная база избыточна; `db.js` сериализует все чтения/записи в одну
  очередь, что убирает гонки при параллельных запросах без установки БД.
- **Собственный i18n** — при трёх известных языках и фиксированном наборе
  экранов простой `t(key)` поверх словаря даёт всё нужное (интерполяция,
  склонения по числу) без лишней зависимости.
- **Разбивка кода по маршрутам (`React.lazy` + `Suspense`)** — страница ленты
  грузится сразу, а код каждой остальной страницы подгружается только при
  переходе на неё; уменьшает первоначальный JS-бандл примерно на 10%.
- **`frontend/vercel.json`** — SPA-переадресация всех путей на `index.html`,
  иначе прямой переход по ссылке вроде `/communities/it_almaty` или обновление
  страницы возвращали бы 404 от хостинга (React Router работает только на
  клиенте, у сервера нет файла на этот путь).

## API

Все эндпоинты, требующие личность, берут её из заголовка
`Authorization: Bearer <токен>`, никогда из тела запроса.

| Метод | Путь | Auth | Описание |
|---|---|---|---|
| POST | `/api/auth/google` | — | обменять Google ID-токен на сессию |
| GET | `/api/posts` | опц. | лента (`tab=recommendations\|following`, `q=`, `communityId=`) |
| GET | `/api/posts/author/:userId` | опц. | посты одного автора |
| POST/PATCH | `/api/posts[/:id]` | обязательна | создать/редактировать пост |
| POST | `/api/posts/:id/like` | обязательна | лайк/анлайк |
| GET/POST | `/api/posts/:postId/comments` | POST обязательна | дерево комментариев / ответ |
| POST | `/api/comments/:id/like` | обязательна | лайк/анлайк комментария |
| GET/PATCH | `/api/users/me` | обязательна | свои настройки / обновить профиль |
| GET | `/api/users/:id` | опц. | публичный профиль — `:id` принимает канонический id, никнейм или короткий номер |
| GET | `/api/users/:id/followers` / `/following` / `/friends` | опц. | списки связей (канонический id) |
| POST | `/api/users/:id/follow` | обязательна | подписаться/отписаться (или отправить заявку) |
| GET | `/api/users/me/follow-requests` | обязательна | входящие заявки на подписку |
| POST | `/api/users/follow-requests/:id/accept` / `/decline` | обязательна | ответ на заявку |
| GET | `/api/notifications` | обязательна | уведомления текущего пользователя |
| POST | `/api/notifications/read` | обязательна | отметить прочитанными |
| GET/POST | `/api/conversations` | обязательна | список переписок / нет тела |
| GET/POST | `/api/conversations/:userId/messages` | обязательна | история / отправить сообщение |
| GET/POST/PATCH/DELETE | `/api/communities[/:id]` | POST/PATCH/DELETE обязательна | список/детали/создать/редактировать/удалить — `:id` принимает канонический id или никнейм |
| POST | `/api/communities/:id/join` / `/leave` | обязательна | вступить (или отправить заявку) / выйти |
| GET | `/api/communities/:id/join-requests` | обязательна (админ) | заявки на вступление |
| POST | `/api/communities/:id/join-requests/:userId/accept` / `/decline` | обязательна (админ) | ответ на заявку |
| GET | `/api/search?q=` | опц. | `{ users, communities }` по имени/никнейму/названию |

## Установка и запуск

Требуется Node.js 18+ и Google-аккаунт для бесплатного OAuth Client ID.

### 1. Google OAuth Client ID

1. [console.cloud.google.com](https://console.cloud.google.com/) → создать проект.
2. **APIs & Services → OAuth consent screen** → "External" → заполнить обязательные поля.
3. **APIs & Services → Credentials → Create Credentials → OAuth client ID**, тип **Web application**.
4. В **Authorized JavaScript origins** добавить `http://localhost:5173` (и домен
   деплоя, если запускаете не только локально).
5. Скопировать **Client ID** (секрет не нужен).

### 2. Переменные окружения

**Backend** (`backend/.env`, скопировать из `.env.example`):
```
JWT_SECRET=любая-длинная-случайная-строка
GOOGLE_CLIENT_ID=xxxxx.apps.googleusercontent.com
```

**Frontend** (`frontend/.env`, скопировать из `.env.example`):
```
VITE_GOOGLE_CLIENT_ID=xxxxx.apps.googleusercontent.com
# при раздельном деплое frontend/backend, иначе не нужно:
VITE_API_BASE_URL=https://ваш-backend.example.com/api
```

### 3. Запустить

```bash
cd backend && npm install && npm start      # порт 4000
cd frontend && npm install && npm run dev   # порт 5173, отдельный терминал
```

Открыть [http://localhost:5173](http://localhost:5173). При первом запуске
`backend/data/db.json` создаётся автоматически из `backend/data/seed.json`, а
всем аккаунтам без своего номера присваивается короткий `publicId` (разовая
миграция при старте сервера).

## Компромиссы и осознанные решения

- **JWT-сессия поверх Google, без серверных сессий/куки** — проще для объёма
  задачи, но украденный токен действителен до истечения срока (30 дней) без
  возможности отзыва.
- **JSON-файл вместо базы данных** — очередь записи в `db.js` устраняет потерю
  данных при параллельных запросах, но не масштабируется на много
  одновременных пользователей.
- **Переписка гейтится живым состоянием подписок**, а не отдельным списком
  "друзей" — если один из двух отпишется, история переписки станет недоступна
  до повторной взаимной подписки.
- **Локальный (без AI API) помощник для постов** — вместо платного внешнего
  API подбор идей и хэштегов идёт по словарю ключевых слов и знакам
  препинания в самом тексте; работает бесплатно и без сетевых вызовов.
- **Ссылки на профиль резолвятся тремя способами** (канонический id, никнейм,
  короткий номер) на паре "детальных" эндпоинтов, а не переписывают всю модель
  данных — все остальные действия (подписка, сообщения, вступление в
  сообщество) как и раньше используют канонический id, полученный после
  первого запроса по никнейму.
- **Аватары как простые SVG-силуэты**, не иллюстрации — стиль плоских иконок,
  узнаваемых по силуэту и одной-двум деталям.
- **Уведомления и открытая переписка опрашиваются (polling)**, а не push/WebSocket.
- **Без изображений в постах, без пагинации** ленты/комментариев/уведомлений —
  вне рамок текущего объёма задачи.

## Известные ограничения

- **Google Sign-In на задеплоенном фронтенде** работает только если домен
  фронтенда добавлен в Authorized JavaScript origins используемого
  OAuth-клиента в Google Cloud Console.
- **Язык самой кнопки Google Sign-In** передаётся явно (`locale`) и следует
  языку интерфейса — но если Google поверх неё показывает свой собственный
  экран выбора аккаунта, его язык определяется языком самого Google-аккаунта
  посетителя, а не нашей страницей; это ограничение платформы Google, повлиять
  на него со стороны сайта нельзя.
- Токен сессии не привязан к устройству/IP и не отзывается раньше истечения
  срока.
- Нет пагинации ленты, комментариев, уведомлений, сообщений и поиска.
